## 1. 録画管理 & 運用安全 (Recording & Operations)

- [x] **録画一覧での複数選択一括削除機能**
  - ツールバーに選択モード切替ボタン（`isReadOnly` 時は安全に非表示）を新設
  - カード表示（サムネイル左上チェックボックス・枠線ハイライト）およびテーブル表示（ヘッダー全選択・各行チェックボックス・行ハイライト）の双方に対応
  - 誤削除防止のため保護中番組（`isProtected: true`）はチェックボックス無効化＆全選択時にも自動除外
  - 画面下部中央にフローティング一括操作バー（選択件数、全選択/全解除、一括削除、終了）を配置
  - `confirmDialog` による確認モーダルを経て順次 DELETE API を実行し、完了時にスナックバーで通知
- [x] **録画中番組の途中完了・取り消し機能（3択アクションモーダル）**
  - 録画進行中の番組に対し、「完了として保存（正常終了・履歴登録）」「中断して保存（未完了・履歴未登録）」「録画を取り消し（ファイル破棄・完全削除）」の3択操作モーダル（`RecordingActionModal.svelte`）を新設
  - 正常終了（`POST /api/recording/:reserveId/finish`）: `isNeedDeleteReservation = true` を維持してストリームを切断し、実時間確定・サムネイル・エンコード・録画履歴（`RecordedHistory`）登録・予約消化を通常通り実行
  - 中断（`POST /api/recording/:reserveId/stop`）: ファイルは保存・エンコードするが未完了扱い（履歴未登録）とし、再放送時などに重複録画の判定対象（録画済み扱い）にならないよう維持
  - 取り消し（`POST /api/recording/:reserveId/discard` / `DELETE /api/recording/:reserveId`）: ストリーム停止後に録画中 TS 実ファイル・DB レコードを物理削除し、予約も削除/スキップ
  - 予約一覧（行・カード・予約詳細モーダル）および番組表（番組詳細モーダル）から録画中番組の操作時に自動連動
- [x] **リードオンリーモード（閲覧専用モード）/ 録画ファイル削除の非表示設定**
  - 誤操作防止（ファミリー利用・閲覧専用端末等）のため、UI 上からの削除・予約変更・ルール編集等の制限とパスワード解除機能を実装
  - `config.yml`（および環境変数 `EPGDECK_ADMIN_PASSWORD`）によるグローバル設定、`allowedOperations`（`liveStream`, `recordedStream`, `download`, `dashboard`, `search`, `rules`, `encode`）の制御、ローカルストレージによるアンロック維持に対応
- [ ] **ルールの優先順位設定**
  - チューナー数不足による競合発生時、どの自動録画ルールを優先するか順位（Priority）を指定可能にする
  - 競合調停アルゴリズム（`ReservationManageModel`）への優先度重み付けの導入
- [x] **サムネイルディレクトリの階層化（シャーディング）と巨大化防止**
  - 単一ディレクトリへの大量ファイル集中によるファイルシステム走査速度低下やエクスプローラーフリーズを防止するため、`recordedId % 100` による2桁サブディレクトリ（`00/`〜`99/`）への分散保存を導入
  - DB の `thumbnail.filePath` に相対パスを保持させることで、既存のルート直下ファイルと階層化ファイルを同一環境内で完全互換（ハイブリッド共存）
  - EPGStation からのインポートデータや過去のフラットなサムネイルを一括で階層構造に再配置・DB更新する CLI ツール `npm run migrate-thumbnails [-- --dry-run]` を新設
  - サムネイル削除およびクリーンアップ（`fileCleanup`）時の空サブディレクトリ自動削除に対応
- [ ] **録画タグ機能（RecordedTag）の引き継ぎ・仕様判断**
  - EPGStation から引き継いだバックエンド実装（DB スキーマ・REST API・録画完了時の自動タグ付与ロジック）が存在するが、フロントエンド UI は本家時代から未実装（`// TODO` のまま放置）
  - EPGDeck として正式に UI（タグ管理、ルール・手動予約での自動付与設定、録画詳細でのバッジ表示・手動付与/解除、タグによる検索・絞り込み）を実装して機能提供するか、あるいは不要な死にコードとしてバックエンドから完全廃止・整理するかを判断
- [x] **ルールで検索**
  - 録画詳細に同じルールの動画をカルーセル表示（現在視聴中番組のハイライト、サムネイル・容量表示、左右スクロール操作対応）。「すべて見る」から該当ルールの全件一覧への直接リンクを設置
  - 録画一覧にルール指定絞り込み（手動録画のみ、全登録ルールからの選択、URL クエリ `?ruleId=...` 連動）およびアクティブバッジ解除機能を追加。一覧各行・カードからルール絞り込みへのクイックジャンプに対応
- [ ] **視聴済み管理**
  - 録画一覧で視聴済みか否かのラベルを表示する。
- [x] **画面設定の機能精査 & PWA (Progressive Web Apps) 連動**
  - これまで `localStorage` 保存のみで機能していなかった設定画面の「PWA (ホーム画面追加)」トグルを、実際の Service Worker 登録・解除ライフサイクル（`initPWA()`, `syncPWAStatus(enabled)`）と完全連動
  - Web App Manifest（`display: standalone`）および iOS メタタグ（`apple-mobile-web-app-capable`, `apple-touch-icon` 等）を整備し、ホーム画面追加時に URL バーのないネイティブ全画面アプリとして起動可能に
  - 動的ビューポート（`h-dvh`）とセーフエリア（`pb-safe`, `pt-safe`）を整備し、iPhone の Home Indicator やノッチとの重なりを防止
- [x] **UI/UX・レスポンシブ・タイポグラフィ最適化**
  - **予約一覧のスマホ最適化**: フィルタータブの合計幅が画面を突き破って「重複」以降が切れる問題を解消。スマホ時はタイトル・手動予約の上段と、カード幅内でスムーズにスワイプできる横スクロールタブの下段の2段構成に最適化
  - **ルール一覧の誤操作防止**: 編集ボタンとゴミ箱（削除）ボタンの間にディバイダー（縦区切り線）とマージンを新設し、通常操作と破壊的操作を物理的・視覚的に明確に分離
  - **タイポグラフィ・概要文字サイズ改善**: 番組概要・詳細テキストを 12px から 14px（`.program-description`, `.program-extended`）に引き上げ、一覧概要スニペットをスマホ 13px / PC 14px（`.program-summary`）に拡大
  - **横スクロールの所作統一**: `app.css` に `@utility no-scrollbar` を新設し、予約一覧・放送中・番組表の横スクロールタブから無駄なスクロールバーを排除
- [x] **ルールのキーワード絞り込み**
  - ルール一覧画面（`/rule`）にキーワード検索バーを設置し、多数の登録ルールから目的のルールを高速にインクリメンタル/Enter絞り込み可能に
  - URL クエリパラメータ（`?keyword=...`）との双方向同期を整備。ダイレクトアクセスやブラウザの履歴移動（戻る・進む）での検索状態復元に対応
  - アクティブなキーワードバッジとワンクリック解除ボタン、および該当件数表示（絞り込み結果: X 件 / 全 Y 件）を実装
  - 検索一致ゼロ件時の案内メッセージと「絞り込みを解除」ボタンの設置、スマホ（390px）・デスクトップ（1280px）両対応のレスポンシブツールバーを整備

## 2. パフォーマンス & フロントエンド (Performance & Frontend)

- [x] **15k録画環境におけるドロップログ肥大化対策 & クリーンアップ最適化**
  - ドロップ・エラーが0件の正常録画時にログ実ファイルを自動破棄（`config.recording.dropLog.deleteOnNoDrop: true`、デフォルト有効）し、微小ファイルの単一ディレクトリ肥大化を根本解決
  - 実ファイルが存在しない場合でも、DB上のドロップ数・エラー数の履歴情報は一切削除せず永続保持するようクリーンアップ処理（`dropLogFileCleanup`）の仕様を抜本改善
  - ディレクトリ走査時に実ファイルリストを先行取得・Set化し、15,000回の `fs.stat` システムコールを全廃してクリーンアップ走査を劇的に高速化
  - 録画詳細画面でのドロップ0件時の案内表示（404抑止）および詳細ログ表示を整備
- [ ] **番組表・ログの仮想スクロール (Virtual Scroll) 導入検討**
  - 番組表（1週間分）やシステムログ（数万行）表示時の DOM ノード数肥大化を抑え、描画負荷とメモリ消費を削減
  - スクロール追従性と既存 CSS グリッドレイアウトとの両立検証
- [x] **スマホ（タッチデバイス）での動画プレイヤー コントロール表示・タップ操作の改善**
  - コントロール非表示時に画面をタップした際は動画を一時停止させずコントロールを表示するのみとし、予期せぬ誤停止を解消
  - コントロール表示時の背景タップによる手動非表示と、再生中3.5秒無操作時の自動フェードアウトタイマーを整備
  - スマホで親指操作しやすい中央クイック操作ボタン群（10秒戻る・大判再生/一時停止・30秒進む）をコントロール表示時に展開
  - シークバー操作中のタイマー保護および各コントロールのイベント伝播遮断（`stopPropagation`）により安定したタッチ操作を実現
