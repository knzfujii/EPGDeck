# EPGDeck (Svelte 5 版) 画面仕様書

本ドキュメントは、[EPGStation 画面仕様書 (オリジナル)](./epgstation_ui_spec.md) をベースとして、モダン Web 技術（Svelte 5 + Vite + Tailwind CSS v4）への刷新および **15,000 件以上の録画アーカイブ運用** を想定した UI/UX 設計・アーキテクチャ仕様をまとめた技術仕様書です。

---

## 1. 設計思想と基本方針

1. **仮想 DOM レスによる圧倒的な軽快性 (Svelte 5 Runes)**:
   - Vue 2 / Vuetify から Svelte 5 ネイティブコンパイルへ移行。
   - CSS サイズを **約 96% 削減 (1.1 MB ➔ 61 kB)**、JS バンドルを **約 76% 削減** し、低スペック端末でも高速動作。
2. **15,000件超の録画アーカイブ最適化**:
   - **「年・月セレクター」** と **「主要ジャンルピル」** により、膨大な録画データへの瞬間ジャンプ・絞り込みを実現。
   - サムネイル階層化（シャーディング）およびドロップ0件ログ自動削除によりファイルシステム負荷を最小化。
3. **動画視聴アプリとしての導線強化**:
   - 各画面からワンクリックで視聴・再生へ移行できる明瞭なアクション配置。
   - プレイヤー自体も映像鑑賞に最適な **直角デザイン (`rounded-none`)** を採用。
4. **デザイントークンとリズムの統一**:
   - 垂直コンポーネント間余白を `space-y-5` (20px)、カード内パディングを `p-4 sm:p-5` に統一。
5. **目的別の 3 セクションナビゲーション**:
   - 「視聴・ブラウズ系（ダッシュボード ➔ 録画一覧 ➔ 番組表 ➔ 放送中）」➔「予約・ルール系（予約一覧 ➔ ルール一覧 ➔ 番組検索）」➔「システム系（エンコード一覧 ➔ システムログ）」。

## 3. 各画面の詳細仕様

### 3.1 ダッシュボード (`/`)
- **2 カラム構成（左: 最新録画、右: 直近予約）**: コンテンツ視聴を最優先とし、左側に録画済み番組、右側に直近予約を配置。
- **カード見出し統一 (16px / font-bold)**: 「ストレージ容量」「録画一覧」「予約一覧」の全主要カード見出しを `text-base font-bold`（16px）+ アイコン `size={18}` で統一し、情報階層の整合性を確保。
- **直近予約一覧の表示制限**: 直近予約リストは直近10件に制限表示（重複スキップは除外。総件数は見出し横バッジに表示され、「すべて見る」から予約一覧画面で全件確認可能）。
- **録画中番組のインライン統合**: 直近予約カードの最上部にパルス付き「🔴 録画中」バッジと進行度バーで表示。「▶ 視聴」および「⏹ 停止」（3択モーダル）を直接操作可能。
- **チューナー競合警告**: 競合発生時のみアコーディオンで警告（正常動作である重複スキップは除外）。
- **厳格な録画中判定**: API `/api/recording` との照合を優先し、フォールバック時も競合（`isConflict`）・スキップ（`isSkip`）・重複（`isOverlap`）を録画中から確実に除外。

### 3.2 放送中 (`/onair`)
- **3 カラムテーブル構成**: `[放送局]`、`[現在の番組 (主役)]`、`[次の番組 (予告)]` の自然な視覚フロー。
- **即時アクション**: 番組名横の「▶ 視聴」、現在番組の「🔴 録画」および録画中の「⏹ 停止」（3択モーダル）、次番組の「+ 予約」/「✓ 予約中」。
- **メタ情報 & ツールバー**: 残り時間表記（`残り 24分` 等）、ジャンルカラーバッジ、進捗バー。放送波タブ（共通コンポーネント `FilterTabs`）、キーワード検索、ジャンルピル絞り込みを完備。

### 3.3 番組表 (`/guide`)
- **全放送波横並び一括表示 & セレクター統一**: デフォルトを「すべて (`all`)」とし、全局を1画面で横スクロール俯瞰。チャンネル列幅は `w-40`（160px）に最適化。放送波切り替えには放送中（`/onair`）や予約一覧と同じ共通コンポーネント `FilterTabs.svelte` を採用し、UIデザイン・アクセシビリティ（WAI-ARIA）・型安全性を共通化。
- **ARIB 規格準拠の日付管理**:
  - **朝 4:00 起点境界**: 深夜帯（0:00〜3:59）は前日のタイムラインとして正しく判定（`getBaseDate()`）。
  - **最大8日間制限**: ARIB EPG 規格に合わせ、当日含め最大8日間（`MAX_DAYS_AHEAD = 7`）に制限。
  - **局名ヘッダー (48px) オフセット**: 現在時刻赤線インジケーター等のオーバーレイは 48px オフセットを加算して配置計算。
- **レイアウト & スクロール最適化**:
  - **動的ビューポート高収容**: `h-[calc(100dvh-...)]` により画面全体のスクロール破損を根絶。
  - **z-index 階層化**: 左上ヘッダー `z-50`、時刻列 `z-40`、局名ヘッダー `z-30`、番組セル `hover:z-20`。
  - **状態維持**: 日付移動時もスクロール位置（`scrollTop`, `scrollLeft`）を維持。過去24時間分の番組情報を保持し早朝や過去番組も閲覧可能。
- **UI・視認性**:
  - 時刻列のクロノグラフ風スタック表記（大文字時間＋右上の "00"）。
  - ダークモード専用の高輝度ジャンルカラー（ボーダー `-400` 系 ＋ 80% ティント背景）。
  - 放送終了番組のディム表示と予約無効化。実在しない放送波（未受信 CS 等）の動的非表示。
  - **放送波セレクターのデザイン共通化**: 放送中ページや予約一覧と同様に共通コンポーネント `FilterTabs.svelte` を適用し、アプリ全体で統一されたセグメントコントロール（ピル型トレイ + 白背景アクティブカード）を提供。


### 3.4 予約一覧 (`/reserves`)
- **録画中番組の直接把握と3択操作**:
  - 進行中の番組には「● 録画中」バッジと進行度バーを表示。最大8件程度のため一覧内で直接確認・操作可能。
  - 「停止」ボタン押下で 3 択モーダル（`RecordingActionModal`）を起動：
    1. **完了として保存 (`finish`)**: 実尺確定・サムネイル作成・エンコード・録画履歴（二重録画防止）登録。
    2. **中断して保存 (`stop`)**: 途中ファイルを保存するが、録画履歴には登録せず再放送時の救済録画を可能にする。
    3. **録画を取り消し (`discard`)**: 録画を即時中止し、書き込み途中のファイルを物理削除。
- **未来の予約管理**: 手動予約の取消、ルール予約のスキップ / 復活（スキップ解除）。
- **共通録画オプション (`RecordingOptionForm.svelte` & `RecordingOptionFormState`)**:
  - TS 保存先（親/サブ）、エンコード設定（最大3系統）、元 TS 削除、末尾欠け許可（`allowEndLack`）を予約モーダル・手動予約・ルール編集で共通コンポーネント化。
- **放映中・録画中予約の保護**: EPG 更新やルール重複調停時に、放映開始済み枠が後発ルールで削除されたりレコーダーが強制終了されるのを多層防御で防止。

### 3.5 ルール一覧 (`/rule`) ＆ ルール作成・編集 (`/rule/edit`)
- **優先度（Priority 1〜10）制御とソート**:
  - チューナー競合時に数値の大きいルールを優先確保。
  - 一覧ソート順を調停アルゴリズムと一致させ、**優先度降順 ➔ ID 昇順** で表示。
- **一覧の検索・状態フィルタ**:
  - キーワード検索バー（URL クエリ `?keyword=...` と双方向同期）。
  - 有効 / 無効 / すべて フィルタタブ（デフォルト: **有効のみ**）。
  - ルール一覧 ⇄ 編集画面間の検索状態・スクロール位置自動復元（`sessionStorage`）。
- **詳細ルール作成・編集 (`/rule/edit`)**:
  - **通常検索 ⇄ 時間指定予約の切替**: 時間指定モードでは検索条件を排し、タイトル・放送局・曜日・時間帯（分単位/日跨ぎ対応）に特化。
  - **未来の録画予定プレビュー**: 編集画面ロード時に自動検索し、ヒット番組の予約状況確認および個別スキップ/復活を直接操作可能。
  - **番組詳細からのキーワード抽出原則**: 記号（`[字]`, `【新】` 等）を除去し、先頭の有効単語を抽出（`extractFirstSearchWord`）。

### 3.6 録画一覧 (`/recorded`) ＆ 録画詳細 (`/recorded/detail`)
- **15,000件最適化**:
  - スリムな2段集約ツールバー（上段: 件数・ルール・年月セレクター、下段: 検索バー・主要ジャンルピル）。
  - 年月セレクター（年・月指定）による過去データへの瞬間ジャンプ。
  - サムネイルの階層化保存（シャーディング: `recordedId % 100` による `00/`〜`99/` ディレクトリ分散）。
  - ドロップ・エラー0件時の詳細ログ実ファイル自動削除（DB集計値は永続保持）。
- **複数選択一括削除**:
  - カード/テーブル両対応の選択モード。保護番組（`isProtected: true`）は自動除外される安全設計。
- **状態維持とシームレス復帰**:
  - 詳細画面から「録画一覧へ戻る」際、直前の検索条件・年月・ページ番号および対象番組位置へ自動スクロール復帰（`sessionStorage`）。
- **録画詳細画面の高度な機能**:
  - **サムネイル再作成**: 任意の秒数（`HH:MM:SS`）を指定してピンポイント再作成。
  - **二重録画防止（履歴）の除外/追加**: 災害報道等で潰れた番組を履歴からワンクリックで除外し、再放送の自動予約を救済。
  - **同一ルール動画カルーセル**: 同じルールで録画された関連番組を横スクロールで一覧・再生。
  - **モバイル対応ヘッダー操作ボタン**: スマホ幅（`< sm`）において「録画一覧へ戻る」➔「戻る」、「重複判定に追加/除外」➔「+重複/重複除外」、「保護する」➔「保護」と文言を自動短縮。全ボタンで改行防止（`whitespace-nowrap shrink-0`）と高さ統一（`h-9 sm:h-10 min-h-0`）を行い、横1列に整然と収まるよう最適化。
  - **生成ファイル一覧の標準化・安全設計**:
    - **カード見出し統一**: `text-base font-bold`（16px）+ アイコン `size={18}` + 件数ピルバッジ（`rounded-full bg-blue-50`）へ統一し、「同じルールの録画」見出しと完全整合。
    - **ファイル情報レイアウト**: 上段にファイル種別バッジ（TS / MP4 / エンコード設定名）と容量・形式タグを配置し、メイン行にファイル名を `text-sm sm:text-base font-bold` で強調表示。狭小画面でもファイル名が圧迫されず高い可読性を確保。
    - **アクションボタンのコンパクト規格化 (`btn-compact` / 36px) と安全分離**: 再生（Primary）、Kodi、外部再生、ダウンロード（Secondary）の各ボタンスタイルをグローバルユーティリティ `btn-compact`（高さ 36px）に統一。ダウンロードボタンはスマホで正方形（`max-sm:btn-icon-compact`）、PCでテキスト付き通常ボタンにレスポンシブ適応。ファイル削除ボタンの前には `divider-v`（物理垂直分離線）を配置し、ソフトローズのアウトライン（`btn-icon-danger-outline btn-icon-compact`）を適用して誤タップを確実に防止。


### 3.7 統合動画プレーヤー (`Watch.svelte` / `VideoPlayer.svelte`)
- **直角デザイン (`rounded-none`)**: 映像鑑賞を邪魔しないシャープな四角スクリーン。
- **HLS キープアライブ & チューナー自動解放**: 10秒ごとの Ping と画面離脱時の即時 DELETE。
- **タッチデバイス向け誤操作防止**:
  - `onpointermove` によるブラウザ合成 `mousemove` の除外（PC ホバー時のみ表示）。
  - 全面透明オーバーレイによる2段階トグル（タップで表示、空き領域タップで非表示）。
  - コントロール非表示時の `inert` 付与による不可視パーツの誤タップ防止。
  - スライダー操作中の自動非表示タイマー一時停止保護。
- **実録画時間（duration）の 3 段階フォールバック**:
  1. ファイル実測 API (`/api/videos/:id/duration`) ➔ 2. DB 実測値 (`recorded.duration`) ➔ 3. 番組予定枠。
  - 途中録画時は実開始時刻 `actualStartAt` で開始日時を補正。
- **シーク制御とポジション保護**:
  - **録画 HLS**: 生成済みバッファ内は即時シーク、バッファ外はサーバー API（`-ss`）を用いたストリーム再生成。
  - **WebM / MP4 トランスコード**: パイプ配信の特性（Cues不在）に合わせ、サーバー API（`-ss`）で再生成。アンロード前に目標時刻とローディング状態を先行確定し、巻き戻り・チラつきを防止。
- **中央クイック操作ボタン群（シーク・再生・透過デザイン）**:
  - 画面中央に 10秒戻し（`10s`）、再生/一時停止、30秒送り（`30s`）の大型丸ボタンをオーバーレイ配置（スマホ・PC両対応）。
  - シークアイコン中央の表記は「+」「-」記号を排したミニマル表記（`10s` / `30s`）に統一。
  - 動画映像の視聴を妨げないよう、白アイコン・白文字の不透明度を 75%（`text-white/75`）に設定し、マウスホバー時に 100%（`hover:text-white`）へ遷移する快適な透過デザインを採用。

### 3.8 番組検索 (`/search`)
- 条件（キーワード、放送波/放送局、ジャンル、時間帯）による未来番組検索。
- 検索結果からワンクリックで詳細ルール作成画面（`/rule/edit`）へ全条件を引き継ぎ遷移。
- 入力クリアボタン（`×`）および `Escape` キーによる検索リセット・URL クエリ初期化。

## 4. データ・状態管理アーキテクチャ

クライアントの状態管理は Svelte 5 Runes を用いたシングルトンストアクラスとしてカプセル化：
- `channels.svelte.ts`: 放送局マスターキャッシュ
- `playerState.svelte.ts`: レジューム再生位置の永続化
- `snackbar.svelte.ts`: グローバルトースト通知
- `theme.svelte.ts`: ダーク/ライトテーマ切り替え
- `router.svelte.ts`: Native Reactive SPA Router
- `readOnly.svelte.ts`: リードオンリーモード状態と権限管理
- `recordingOptionForm.svelte.ts`: 録画オプションフォーム状態の一元化

## 5. リードオンリーモード（閲覧専用モード）仕様

- **UI 制御**:
  - ヘッダーに「🔒 閲覧専用」「🔓 管理者モード」バッジを表示。
  - 閲覧専用時は削除・予約変更・保護トグル等の破壊的操作ボタンを非表示化。
  - 許可設定（`allowedOperations`）に応じてダッシュボード・検索・ルール一覧等の表示/非表示を動的制御。
- **バックエンド多層防御**:
  - Hono `readOnlyMiddleware` により、未認証の更新系リクエスト（POST, PUT, DELETE, PATCH）および非許可 API を `403 Forbidden` (`readOnlyMode`) で確実に遮断。

## 6. PWA・モバイル最適化・システム連携

- **PWA (Progressive Web Apps)**:
  - 最小構成 Service Worker によりキャッシュ事故（新バージョン不反映・ストリーミング妨害）を防止しつつネイティブ全画面起動を実現。
- **動的ビューポート & セーフエリア**:
  - `h-dvh` と Tailwind v4 セーフエリアユーティリティ（`pb-safe`, `pt-safe`）により iPhone の Home Indicator やノッチとの干渉を防止。
- **外部プレイヤー連携 (URL Scheme)**:
  - スマホ・タブレットの録画詳細画面に「外部再生」ボタンを配置し、VLC 等の外部アプリを URL スキーム / インテントで直接起動。
- **モバイル・タブ復帰時の自動ステータス同期 (`ForegroundRefreshManager`)**:
  - Page Visibility API および `pageshow` を監視し、スリープ復帰時や Socket.IO 再接続時に自動で最新ステータスを再フェッチ。

## 7. コンポーネント・UI スタイル共通化と操作安全設計（デザインシステム）

### 7.1. 共通コンポーネント化 (`client/src/lib/components/common/`)
- **Tailwind CSS Utility-First 原則と Svelte 5 コンポーネントへの全面移行**:
  - `app.css` に定義されていた独自クラス（`.btn-*`, `.form-*`, `.divider-v`, `.card-base` 等）を完全撤廃。CSS に独自コンポーネントクラスを濫造するアンチパターンを排除し、Tailwind CSS の局所性（Locality of Behavior）と Svelte 5 の共通 UI コンポーネントへ全面移行。
- **`Button.svelte` / `IconButton.svelte`**:
  - 主要バリアント（`primary`, `secondary`, `danger`, `danger-outline`, `ghost`）とサイズ（`sm` (32px), `compact` (36px), `md` (40px)）を props で統一。正方形のアイコン単体操作には `IconButton`、テキスト付きやテキストのみの操作には `Button` を使い分け。`<a>` タグとのポリモーフィック対応（`href` 属性）もサポート。
- **`Divider.svelte`**:
  - 垂直（`vertical` / 22px / 幅1px）および水平（`horizontal` / 幅100% / 高さ1px）の視覚的境界線。アクション群と破壊的操作の物理的分離を担う。
- **`Input.svelte` / `Select.svelte` / `Textarea.svelte` / `Checkbox.svelte`**:
  - 高さ 40px（`h-10`）、フォーカスリング、ダークモード、`bind:value` / `bind:checked` に完全対応した標準フォームコントロール。
- **`Card.svelte`**:
  - パディング・枠線・背景・シャドウを統一したコンテナコンポーネント。
- **`Badge.svelte`**:
  - 放送波種別（GR/BS/CS/SKY）、予約種別（ルール/手動）、ステータス（保護中/録画中/競合/スキップ/重複）のバッジ仕様を一元化。サイズバリエーション（`xs`, `sm`, `md`）と視覚アイコン（Lock, Radio, AlertTriangle 等）を内蔵。
- **`SearchInput.svelte`**:
  - 虫眼鏡アイコン、Escape キーによる入力クリア、クリアボタン (X)、44px タッチ領域、インセット余白を標準化した検索ボックス。
- **`FilterTabs.svelte`**:
  - 横スクロール（`no-scrollbar`）、アクティブインジケーター、件数バッジ付きのタブナビゲーション。
- **`PageHeader.svelte`**:
  - アイコン、タイトル、サブタイトル、アクションエリアを内包し、画面端余白を確保した統一ヘッダーカード。
- **`ReadOnlyGuard.svelte`**:
  - 各画面で重複していた「閲覧専用モード案内カード」を一元化。
- **`LoadingState.svelte` / `EmptyState.svelte`**:
  - データ取得中および 0 件時の表示レイアウトとアイコン・アクションボタンを標準化。

### 7.2. 削除・破壊的ボタンの安全設計（誤操作防止）
- **パーティションによる物理的分離 (`<Divider orientation="vertical" />`)**:
  - 通常の操作ボタン（再生・詳細・保護・編集・画面クリア等）と破壊的操作ボタン（削除・録画停止・キャンセル・サーバーログ消去等）の間に垂直ディバイダーを挟むことで、指の誤タップを物理的に防止。
- **控えめなアウトライン化 (`variant="danger-outline"`)**:
  - 誤操作しやすいベタ塗りの警告赤ボタンから枠線主体の控えめなスタイルへ変更し、視覚的な誤認・誤タップを抑制。
  - カラー設計は「デフォルトは淡い赤（ソフトローズ）で控えめに危険性を示し、ホバー・フォーカス時に明確な警告赤へと変化」する二段階表現を採用。

### 7.3. モバイル画面端タッチ保護（インセット余白）
- **母指球・手のひら誤接触防止**:
  - スマホ（390px）などの画面端やカード右下角にボタンが直付けされていると、片手操作時に手のひら（母指球）が誤接触しやすいため、テーブル行右端に `pr-5 sm:pr-6`、カード右端に `mr-1 sm:mr-2` 等の十分な安全マージンを確保。
- **44px タッチターゲット保証**:
  - スマートフォン操作時のタップミスを防止するため、主要な操作ボタンに最小 44px のタップ領域を確保。

### 7.4. フォームコントロール・ボタン・ヘッダーの標準化
- **フォーム部品・主要ボタンの 40px（`h-10` / `size="md"`）統一**:
  - 全画面（番組検索、録画一覧、ルール一覧、番組表、各種モーダル）のツールバー、検索入力バー・セレクトボックス・主要アクションボタンの高さを 40px（`2.5rem` / フォント 14px `text-sm` / 角丸 `rounded-xl`）で統一し、画面間の視覚的統一感を担保。
- **一覧行・カード内アクションの 36px（`size="compact"`）階層化**:
  - テーブル行内やカード内の操作ボタン（再生、視聴、停止、スキップ、保護、削除）は、行の高さを圧迫せず視覚的ノイズを抑えるため、高さ 36px（`2.25rem` / フォント 12px `text-xs font-bold` / 角丸 `rounded-lg`）の `size="compact"` に統一。
- **ヘッダー・ツールバーアイコンボタン (`variant="ghost"`)**:
  - 枠線・背景のない透過ゴーストボタン（40×40px / `rounded-xl`）を `IconButton variant="ghost"` として定義し、メニュー開閉やテーマ切替のスタイルを統一。
- **ヘッダーサブタイトルの文字サイズ統一と冗長説明文の排除**:
  - 画面タイトルのサブタイトルを `text-xs sm:text-sm text-slate-500 dark:text-slate-400 mt-0.5`（スマホ 12px / PC 14px）で完全統一。
  - 「説明が必要な時点でデザインの敗北」という方針に基づき、操作説明（「クリックで詳細確認・キャンセル」等）やアプリ説明調の文章を徹底排除。
  - 一覧系画面のステータス表現をミニマル構文（通常時: `全 X 件`、絞り込み時: `X 件 / 全 Y 件`、ページネーション時: `X - Y 件 / 全 Z 件`、放送中: `全 X 局` / `X 局 / 全 Y 局`）に完全統一。
