# EPGDeck (Svelte 5 版) 画面変更仕様書

本ドキュメントは、[EPGStation 画面仕様書 (オリジナル)](./epgstation_ui_spec.md)
をベースとして、2026 年のモダン Web 技術（Svelte 5 + Vite 8 + Tailwind CSS v4）への移行、および
**15,000 件以上の録画アーカイブ運用** を想定した UI/UX の最適化・統廃合・新機能仕様をまとめた変更設計書です。

---

## 1. 刷新の基本方針と設計思想

1. **仮想 DOM レスによる圧倒的な軽快性 (Svelte 5 Runes)**:
    - 従来の Vue 2 (仮想 DOM + 重厚な Vuetify) から Svelte 5 のネイティブ DOM コンパイルへ移行。
    - CSS サイズを **約 96% 削減 (1.1 MB ➔ 61 kB)**、JS バンドルを **約 76% 削減**
      し、モバイルや低スペック端末でも極めて高速に動作。
2. **15,000件超の録画アーカイブ特化**:
    - 従来のページ番号移動だけでは困難だった過去データへのアクセスを、**「年・月セレクター（年月ジャンプ）」** と
      **「ジャンルチップ絞り込み」** で瞬時に検索・閲覧可能に。
3. **動画再生アプリとしての導線強化**:
    - 目的である「番組を見る・再生する」を最優先とし、各画面で
      **ワンクリックで即座に再生できる目立つ導線（鮮やかな再生ボタン・サムネイルオーバーレイ）** を配置。
    - プレイヤー自体も映像鑑賞に最適な **シャープな四角（直角デザイン / `rounded-none`）** を採用。
4. **デザインシステム（デザイントークン）の完全統一**:
    - 全画面の垂直コンポーネント間余白を **`space-y-5` (20px)**、ヘッダーカードを **`p-4 sm:p-5`**
      に統一し、一貫性のあるリズム感と視認性を実現。

>
> - **ストレージ容量 (`/storages`)**: 独立画面を廃止し、ダッシュボード（`/`）へストレージ使用量カードとして統合。

>   `POST /api/recorded/cleanup` のみバックエンドに残存）。

## 3. 各画面の詳細仕様

### 3.1 ダッシュボード (`/`)

- **直近の予約（録画中番組の統合・直接操作）**:
    - 画面内での重複表示を防止し、最上部の独立セクションではなく「直近の予約」一覧カード内で録画中番組（`🔴 録画中`
      バッジ、進行度バー）を自然に表現。
    - 各録画中番組に **青色の「▶ 視聴」ボタン**（ライブ/追っかけ視聴）および
      **「⏹ 停止」ボタン**（押下で完了/中断/破棄の 3 択モーダル起動）をインライン配置。
    - 競合警告・重複スキップバッジ付き。
    - **録画中判定の共通化と厳格化 (`recording.ts`)**: 画面上の録画中判定（`isReserveCurrentlyRecording`）において、API
      `/api/recording`
      の実録画プロセス照合を優先しつつ、フォールバックの時間判定でスキップ（`isSkip`）や重複無効（`isOverlap`）に加え、**チューナー競合（`isConflict`）も確実に録画中から除外**
      してステータス表示の不整合を根絶。
- **最新の録画済み**:
    - 最新の録画完了番組をサムネイル・容量・日時とともに一覧表示。
    - 青色の **「▶ 再生」** ボタンから即座にストリーミング視聴へアクセス可能。

### 3.2 放送中 (`/onair`)

- **洗練された 3 カラムテーブル構成**:
    - `[放送局]`、`[現在の番組 (主役)]`、`[次の番組 (予告)]` の左から右への自然な視覚フロー。
    - **番組タイトル直近のアクション配置**:
        - 番組名のすぐ傍に **「▶ 視聴」ボタン** を配置し、最重要アクションへ即座にアクセス可能。
        - **現在番組の即時録画（新機能）**: 未録画時は
          **「🔴 録画」ボタン**（押下で即座に予約発行し途中録画開始）、録画中はパルス付きステータス「● 録画中」および
          **「⏹ 停止」ボタン**（押下で完了/中断/破棄の `RecordingActionModal`
          を起動）。録画停止・中断 API 呼び出し時は、`RecordedItem.id` ではなく `ReserveItem.id`
          を正しく特定して送信し、確実に中断・保存を実行。
    - **メタ情報と進捗の視覚化**:
        - 放送時間、**残り時間表記（`残り 24分` 等）**、**ジャンルカラーバッジ**、スムーズなプログレスバーを統合。
    - **次の番組の予約状態連携**:
        - 未予約時は **「+ 予約」ボタン**、予約済み時は
          **「✓ 予約中」バッジ**（二重予約を防止し、クリックで予約一覧へ遷移）。
    - **ツールバーと絞り込み機能**:
        - 放送波タブ（すべて/地デジ/BS/CS/SKY）に加え、**リアルタイムキーワード検索バー** ＆
          **ジャンルチップ絞り込み**（ニュース、アニメ、ドラマ等）を完備。
    - **配信設定モーダル & チューナー案内**:
        - 「視聴」ボタン押下時にモーダルが展開（ストリーム形式 `M2TS-LL`, `WebM`, `HLS` と画質選択）。
        - ライブ視聴時はチューナー確保に関する注意案内を表示。チューナー不足時（Mirakurun
          503）は「利用可能なチューナーがありません（現在すべてのチューナーが録画で使用されています）」と分かりやすいエラーメッセージを表示。

#### 3.3 番組表 (`/guide`)

- **全放送波（「すべて」）のデフォルト表示**:
    - 放送波セレクターのデフォルトを「すべて (`all`)」とし、地デジ・BS・CS・SKYの全受信チャンネルを1つの番組表グリッド上に横並びで一括表示。
    - 各局名ヘッダーに `[GR]` `[BS]`
      などのカラーバッジを配置し、複数放送波が混在しても一目で局種別を識別可能。従来通り個別タブ（「地デジ」など）による絞り込みも可能。
- **コンパクトなチャンネル列幅**:
    - `w-40`（160px、従来の約 70%）に最適化し、1画面で多数の放送波・チャンネルを同時に俯瞰。
- **堅牢なタイムスケール固定とレンダリング最適化**:
    - **スタッキングコンテキストの z-index 階層化**: 横スクロール時に左端の時刻表示が局名ヘッダーやスクロール要素に隠れないよう、左上ヘッダーを
      `z-50`、時刻スケール列を `z-40`、局名ヘッダーを `z-30`、番組セルを `hover:z-20` と厳格に階層化。
    - **Svelte 5 `{#each}`
      キー指定**: チャンネル列（`col.channel.id`）および番組セル（`prog.id`）に明示的なキーを指定し、差分更新を最小化。
- **タイトル ＆ 概要の最大化**:
    - 各セル内の開始時間表示を削除し、短時間の番組でもタイトルや概要文が最上段からしっかり読めるレイアウト。
- **鮮明なダークモードジャンルカラー**:
    - 黒背景に沈まない高輝度ボーダー（`-400`系）と 80% リッチティント背景（`dark:bg-*-950/80`）でスタイリッシュに発色。
- **4:00 起点の日付境界（深夜帯の基準日判定）**:
    - 日本のテレビ放送（ARIB/EPG規格）のタイムラインは「朝 4:00〜翌朝 4:00」が 1 日。
    - 深夜帯（0:00〜3:59）はカレンダー上の翌日でも「前日のタイムライン」に属するため、単純なカレンダー日付比較ではなく、基準日算出（`getBaseDate()`）や表示範囲 Unixtime（`guideStartAt <= now && now < guideEndAt`）を用いて厳格に判定。
- **局名ヘッダー（48px）のオフセット加算**:
    - 局名ヘッダー（`HEADER_HEIGHT = 48px` = `h-12`）直下をグリッドの `top: 0`
      とするレイアウトにおいて、現在時刻赤線インジケーター等の親コンテナ直下配置オーバーレイは、必ず 48px オフセットを加算して配置計算。
- **番組表ロジックの純粋関数化 (`client/src/lib/utils/guide.ts`)**:
    - 現在時刻線の座標計算、スクロール目標位置、日付・深夜帯判定などは独立した純粋関数として集約し、Vitest で網羅的に境界値テストを担保。
- **未受信放送波の動的非表示**:
    - Mirakurun から取得した実在チャンネルリストから、受信実績のある放送波種別（`GR`, `BS` 等）を
      `channelStore.activeChannelTypes`
      で算出し、実チャンネルが存在しない放送波（未契約・未受信の CS/SKY 等）は番組表および OnAir タブから自動非表示。
- **番組詳細ポップアップからの録画中番組操作連携**:
    - 番組表上の番組セルをクリックした際、対象番組が録画中（`/api/recording`
      に存在）であれば、予約キャンセルではなく後述の「3択操作モーダル（`RecordingActionModal`）」を起動。
- **放送終了番組のディム表示 ＆ 予約無効化**:
    - 放送が終了した番組（`prog.endAt <= now`）のセルは、透過度と彩度を抑えたディム表示（`opacity-50 grayscale-[40%] bg-slate-100/80 dark:bg-slate-900/60 dark:opacity-40`）を適用し、現在放映中・未来の番組と一目で区別可能。
    - 番組詳細モーダルでは、未予約の放送終了番組に対して「録画予約する」ボタンを非活性化し「放送終了」表示とするとともに、不要な録画オプション入力欄の代わりに放送終了案内を表示。
- **EPG過去24時間保持による過去番組の閲覧・照合**:
    - `EPGUpdateManageModel.deleteOldPrograms` にて過去24時間の番組情報を保持（`now - 24h` 以前のみ削除）。
    - 朝4時起点境界で表示される番組表において当日早朝や過去の番組が消えずに表示され、録画完了時の番組情報引き継ぎも確実に機能。

### 3.4 予約一覧 (`/reserves`)

- **録画中ステータス・進捗表示 & ライブ視聴連携**:
    - `/api/recording` を並行取得し、録画進行中の番組に赤丸パルス付き「● 録画中」バッジと進行度プログレスバーを表示。
    - 上部フィルタータブに「録画中 (N)」を追加し、現在録画中の番組のみを瞬時に絞り込み可能。
    - 各行および詳細ポップアップからワンクリックで「視聴（ライブストリーミング）」へ遷移。
- **録画中番組の操作モーダル（パターンA：3択アクション）＆「停止」ボタン統一**:
    - 録画進行中の番組ではボタン表示が「停止」（`Square` アイコン）に切り替わり、押下時に `RecordingActionModal`
      を起動。全画面（ダッシュボード、予約一覧、番組表、放送中）で録画中アクションボタンの文言を「停止」に統一。
        1. **完了として保存 (`POST /api/recording/:reserveId/finish`)**: 録画ストリームを正常切断し、実尺確定・サムネイル作成・自動エンコード・録画履歴（`RecordedHistory`）登録・予約消化の通常完了シーケンスを実行。二重録画防止が機能する。
        2. **中断して保存（未完了扱い） (`POST /api/recording/:reserveId/stop`)**: 途中のファイルを保存・エンコードするが、未完了扱いとして
           **`RecordedHistory`
           には登録しない（重複録画の判定対象・録画済み扱いにならない）**。再放送時などに救済録画が可能。
        3. **録画を取り消し（ファイルを破棄） (`POST /api/recording/:reserveId/discard`)**: 録画を即時中止し、書き込み途中の TS ファイルや DB レコードを物理削除して完全クリーンアップ。
    - **終了直後レースコンディションの安全設計**:
        - モーダル操作時に直前で番組が終了していた場合でも、API 側で存在チェックにより例外を投げず安全にスルー（HTTP
          200）して UI を破綻させない。
- **キャンセル・スキップ管理（未来の予約）**:
    - 手動予約は「キャンセル（予約取消）」、ルール予約は「キャンセル（重複スキップ）」として即時反映。
    - スキップ中の番組には「復活（スキップ解除）」ボタンを配置。
- **手動時間指定予約 (`/reserves/manual`) ＆ 録画オプション共通化**:
    - **時間指定手動予約のバグ修正**: EPGStation/EPGDeck
      API 仕様に準拠し、`timeSpecifiedOption: { name, channelId, startAt, endAt }`
      およびフルオプションを正しく送信するよう修正。
    - **録画オプション共通コンポーネント (`RecordingOptionForm.svelte`)**:
        - 番組表予約モーダル（`Guide.svelte`）、予約詳細・編集モーダル（`Reserves.svelte`）、手動予約ページ（`ManualReserve.svelte`）、ルール編集ページ（`RuleEdit.svelte`）でコピペされていた録画オプション UI・状態管理・ペイロード構築ロジックを共通化。
        - TS 保存先（親ストレージ選択、サブフォルダ指定）、エンコード設定（最大3系統、モード・親/サブ指定）、元 TS 自動削除フラグ、チューナー競合時の末尾切れ許可（`allowEndLack`）をどの予約画面・ルール編集画面からも統一的に操作可能。
- **放映中・録画中予約の保護と多層防御による録画継続性保証**:
    - EPG 更新（番組表再取得）や複数ルールの同一番組重複調停において、すでに放映開始済み（`startAt <= now`）の既存予約枠が後発ルールによって横取り・削除（`diff.delete`）されることを
      `ReservationManageModel.sortReserve` で根本防止。
    - さらに `RecordingManageModel` にて `isRecording === true`
      のプロセスに対する強制キャンセルを確実にスキップし、同一枠での新規レコーダー重複起動も抑止する多層防御により、録画の意図しない中断・分断事故を完全に排除。

### 3.5 ルール一覧 (`/rule`)

- **キーワード検索・高速インクリメンタル絞り込み**:
    - ルール一覧画面上部にキーワード検索バーを新設。多数の登録ルールからキーワード・除外キーワード・対象局・ジャンル等を対象に、リアルタイムまたは Enter で瞬時に絞り込み可能。
    - **URL クエリパラメータ同期 (`?keyword=...`)**: 検索ワードは URL と双方向同期され、ダイレクトアクセスやブラウザの「戻る・進む」履歴移動でも検索状態を完全に復元。
    - **アクティブバッジ & 件数表示**: 検索実行時にアクティブバッジとワンクリック解除ボタン、および「絞り込み結果:
      X 件 / 全 Y 件」を表示。0件時は親切な案内と解除ボタンを配置。
- **実予約数の集計バッジ表示**:
    - `/api/reserves` から各ルールの実予約数を取得し、`4 件` などの青色バッジで表示。
- **ルールの優先度（Priority）制御・一覧識別表示 (`Rule.svelte` / `RuleEdit.svelte`)**:
    - 各ルールに 1 〜 10 の優先度（デフォルト:
      5）を設定可能。チューナー競合時に数値の大きいルールが優先的に録画枠を確保。あえて 1〜4 に下げることで競合時に譲る運用や、6〜10 に上げて確実に確保する運用に対応。
    - ルール編集画面（`RuleEdit.svelte`）の予約設定セクションに 1〜10 のセレクトボックスと優先度レベルバッジ（最高:
      8〜10、高: 6〜7、標準: 5、低: 1〜4）を配置。
    - **ルール一覧（`Rule.svelte`）の視認性最適化（全件表示＆バッジ過多防止）**:
        - **デスクトップ（テーブル表示）**: キーワード列から優先度バッジを撤去し、専用の「優先度」列を新設。標準（5）も控えめな枠線・背景付きバッジ
          `5` で統一し（未設定のバグに見えるのを防止）、高優先度（★ 8〜10, ▲ 6〜7）および低優先度（▼
          1〜4）は色付きチップで強調し、縦一列で直感的に比較可能。さらに、操作列（`w-px whitespace-nowrap`）の幅固定に加え、検索キーワード（`min-w-[200px]`）・対象局/ジャンル（`min-w-[130px]`）・保存先（`min-w-[150px]`）・エンコード（`min-w-[110px]`）等に適切な最小幅を保証し、中画面サイズ（768px〜1280px）でのコンテンツ列の押しつぶされを防止。
        - **スマホ（カード表示）**: キーワードの横ではなく、右端の予約数バッジの隣に整然と配置。標準は
          `優先度 5`、高・低はアイコン付き（`★ 10`, `▼ 2`）でメリハリを付けて表示。
    - **対象放送局の名称表示**:
        - 他画面を経由せず直接 `/rule`
          を開いた場合やリロード時でも確実に局名（例: 「BS日テレ」）が表示されるよう、画面初期ロード時にチャンネルマスター（`channelStore.fetch()`）を自動取得し、未取得時のフォールバック表記（`ch:400101`）を防止。
- **詳細ルール作成・編集ページ (`/rule/edit`)**:
    - モーダルではなく独立ページとして実装し、縦長レイアウトで全項目を一括編集可能。
    - **通常検索 ⇄ 時間指定予約のタブ切り替え**:
        - 画面上部に「通常検索ルール」と「時間指定予約ルール」のモード切替タブを配置。
        - **時間指定予約モード**:
            - 番組表データに依存せず、指定した放送局・曜日・時間枠を定期自動録画する専用ビューを提供。
            - 不要な検索オプション（除外キーワード、正規表現、ジャンル絞り込み、番組長、期間等）を排し、「録画タイトル（番組名）」「対象放送局（必須）」「対象曜日」「時間帯（開始時刻
              `<input type="time">` 〜 終了時刻 `<input type="time">`）」に特化したシンプルなフォーム構成。
            - 分単位（HH:mm）指定および日跨ぎ枠（例: 23:00 〜 01:00）に完全対応し、バックエンドの `ReserveOptionChecker`
              / `ReservationManageModel` と連携して正確なミリ秒精度で予約枠を生成。
    - **基本検索条件（通常検索モード）**:
        - **キーワード（任意）**: 未指定時は全番組が対象（ジャンルや時間帯・放送局のみでのルール作成を完全サポート）。キーワード未指定時または空文字時は対象項目フラグ（番組名/概要等）の有無にかかわらずバリデーションを通過させ、DB 上は
          `null` として正規化保存。一覧では `(全番組)` と明示表示。
        - **除外キーワード**: キーワードと同様に対象（番組名/概要/詳細）の自動補完に対応。
        - **曜日・時間帯の指定（`times`）**: 番組の長さの上段に配置。曜日選択（全曜日/平日/土日切替、視認性の高い統一青トーン＆ダークモード非選択時の落ち着いた暗色配色）＋開始時刻
          `<input type="time">`・終了時刻
          `<input type="time">`（分単位対応、終日・全時間帯クリア対応）。対象曜日が0個の場合は保存前にわかりやすいエラーを提示。DB 検索層（`ProgramDB`）では
          `Set` により重複時を排除し、24時間すべてが含まれる場合は `startHour` 条件を自動省略して SQL を最適化。
        - **番組の長さ**: 最小/最大分（最小値 > 最大値の逆転時は保存前に警告表示）。**検索対象期間（`searchPeriods`：開始日時〜終了日時ピッカー）**
    - **詳細条件（アコーディオン）**:
        - ジャンル・サブジャンル絞り込み（一括選択・除外対応）
        - 放送波（GR/BS/CS/SKY）および放送局の個別指定優先モード（放送局指定時は放送波フラグを自動的に無効化・分離しバリデーション競合を防止）
        - **録画ファイル名フォーマット（`recordedFormat`）**: 詳細条件内で個別ルールごとの命名形式を柔軟に指定
    - **未来の録画予定プレビュー & スキップ管理（詳細条件の直後）**:
        - 「録画予定を検索する」ボタンにより、現在の設定条件に合致する未来の放送番組（`POST /api/schedules/search`）をリアルタイム検索。
        - 予約データ（`GET /api/reserves`）と自動照合し、「録画予約中」「スキップ中」「競合中」「重複」「未予約」の状態バッジを表示。
        - 予約番組ごとに**「スキップ」および「スキップ解除」**をワンタップで直接トグル可能。
    - **予約設定 & 録画オプション**:
        - 有効/無効、二重録画防止（重複回避日数 `periodToAvoidDuplicate` 指定対応）、無料放送限定。
        - 共通コンポーネント `RecordingOptionForm`
          による TS 保存先（親/サブ）・エンコード設定（最大3系統）・元 TS 自動削除・末尾切れ許可の統合指定。
    - **番組詳細からのルール検索・作成連携とキーワード抽出原則**:
        - 番組詳細ポップアップから「ルール作成」や「類似検索」へ遷移する際、番組名そのままではなく、EPGStation 互換の記号除去（`[字]`,
          `【新】`, `［字］`, `〈アニメ〉`, `《映画》`, `「」`
          等）を行い、先頭の有効単語を抽出（`extractFirstSearchWord`）して検索ワードとして設定。
    - **検索画面 (`/search`) からの条件引き継ぎ**:
        - キーワードだけでなく、ジャンル（`genre`/`subGenre`）や放送局（`channelId`）の指定を URL クエリから確実に復元し、キーワード未指定時でも詳細設定を自動展開して条件を完全反映。
        - 番組検索画面自体もキーワードなしでのジャンル単体検索に対応し、ジャンル別番組確認からルール作成までのシームレスな動線を提供。

### 3.6 録画一覧 (`/recorded`) ＆ 録画詳細 (`/recorded/detail`)

- **15,000件最適化**:
    - 年月セレクター（`2026年` × `8月` など）とジャンルチップ絞り込み。
    - **ドロップログの最適化（15kアーカイブ対策）**:
        - エラー・ドロップ・スクランブルが0件の録画は詳細ログ実ファイルを自動削除（`config.recording.dropLog.deleteOnNoDrop: true`、デフォルト有効）し、単一ディレクトリ内の微小ファイル肥大化を根本解決。
        - ログ実ファイルの有無にかかわらず、DB上のドロップ集計値（`dropCnt: 0`）および録画一覧のバッジ表示は永続保持。
        - 録画詳細モーダルでは0件時に「ドロップ・エラーは検出されませんでした（正常）」と分かりやすく案内し、不要な 404
          API 呼び出しを抑止。
        - ドロップ発生時は実ファイルから整形された詳細ログを表示（実ファイル不在時でもドロップ数サマリーを確実に表示）。
    - **サムネイルディレクトリの階層化（シャーディング）と巨大化防止**:
        - 単一ディレクトリへのファイル集中によるファイルシステム走査速度低下を防止するため、`recordedId % 100`
          による2桁サブディレクトリ（`00/`〜`99/`）への分散保存を導入。
        - DB の `thumbnail.filePath`
          に相対パスを保持させることで、既存のルート直下ファイルと階層化ファイルを同一環境内で完全互換（ハイブリッド共存）。
        - 既存のフラットなサムネイルを一括で階層構造に再配置・DB更新する CLI ツール
          `npm run migrate-thumbnails [-- --dry-run]` を提供。
- **複数選択一括削除機能**:
    - ツールバーに選択モード切替ボタンを新設（リードオンリーモード時は安全に非表示）。
    - **カード & テーブル両対応**: カード表示（サムネイル左上チェックボックス・青枠線ハイライト）およびテーブル表示（ヘッダー全選択・各行チェックボックス・行ハイライト）の双方に対応。
    - **保護番組の二重安全設計**: 誤削除防止のため保護中番組（`isProtected: true`）はチェックボックスが無効化され、全選択操作時にも自動除外。
    - **フローティング一括操作バー**: 選択モード時、画面下部中央にフローティングバー（選択件数表示、全選択/全解除、一括削除ボタン、選択モード終了ボタン）を展開。
    - `confirmDialog` による確認モーダルを経て順次 DELETE API を実行し、完了時にスナックバーで通知。
- **ルールで検索・カルーセル表示 & ルール絞り込み**:
    - **同一ルールの動画カルーセル（録画詳細画面）**: 録画詳細モーダル内に同じ自動録画ルールで録画された番組を横スクロールカルーセルで表示（現在視聴中番組のハイライト、サムネイル・容量表示、左右スクロールボタン完備）。「すべて見る」から該当ルールの全件一覧への直接リンクを設置。
    - **録画一覧でのルール指定絞り込み**: 録画一覧ツールバーから「手動録画のみ」または全登録ルールを選択して瞬時に絞り込み可能。URL クエリ（`?ruleId=...`）と双方向同期し、アクティブバッジとワンクリック解除ボタンを配置。一覧各行・カードのルール名からルール絞り込みへのクイックジャンプに対応。
- **録画詳細画面**:
    - サムネイル画像表示（`/api/thumbnails/:id`）、録画ファイルサイズ、保護トグル、エンコード追加モーダル、ドロップログ詳細モーダル。
    - **サムネイル再作成機能（時:分:秒 指定 ＆ 番組共通の秒数記憶）**:
        - サムネイル右上に再作成ボタン（カメラアイコン）を設置。
        - 任意の抽出位置を「時:分:秒」（`HH:MM:SS` または `MM:SS`）で指定してピンポイントで再作成可能。
        - 繰り返し実行や他の番組への適用がスムーズに行えるよう、最後に指定した秒数を番組共通でローカルストレージに記憶・引き継ぐ設計。
        - 再作成時は既存サムネイルを自動でクリーンアップ・置換し、キャッシュバスター付きで即座に画面反映。
        - サムネイル実ファイル不在時の取得例外を 500 から `404 Not Found` に適正化し、削除時のファイル不在（ENOENT）も正常終了として安全に処理。

### 3.7 統合動画プレーヤー (`Watch.svelte` / `VideoPlayer.svelte`)

- **四角（直角）デザイン (`rounded-none`)**:
    - 余計な角丸を排し、映像鑑賞に最適なシャープな直角スクリーン。
- **HLS キープアライブ ＆ 自動チューナー解放**:
    - 10秒ごとのキープアライブ Ping と、画面離脱・ストリーム終了時の自動 DELETE によるチューナーの即時解放。
- **番組タイトル表示のフォールバック・安全性向上**:
    - 番組情報取得完了後にタイトルが空の場合でも、見出しが「読み込み中...」のまま固まらず「（タイトルなし）」と明示表示（通信中は「読み込み中...」）。
    - 時間指定予約において EPG 番組データが存在しない場合でも、`RecorderModel` および `RecordingUtilModel`
      で予約時の設定タイトル（`reserve.name`）を確実に引き継ぎ、空文字や「番組名なし」への化けを完全防止。
- **タッチデバイス（スマホ・タブレット）向けタップ操作・誤爆防止仕様**:
    - **動画本体直結クリックの廃止と全面オーバーレイ**:
        - `<video>` タグ直結のクリック再生トグルを排し、全画面透明オーバーレイ（`z-10`）でタップを判定。
        - コントロール非表示時に画面をタップした際は動画を一時停止させずコントロールを表示するのみとし、コントロール表示時に背景をタップした際は即座に非表示化。
    - **合成 `mousemove` の遮断**:
        - タッチデバイスでタップ直前にブラウザが合成発行する `mousemove`
          による意図しないタイマーリセット・誤動作を防ぐため、`onpointermove` / `onpointerleave` を採用し
          `pointerType === 'touch'` を明示的に無視。
    - **不可視コントロールの無力化**:
        - コントロール非表示時は下部バーに `inert` および `pointer-events-none`
          を付与し、見えないパーツへの誤タップやフォーカスを完全に防止。
    - **シークバー・スライダー操作中のタイマー保護**:
        - スライダーのドラッグ中（`onpointerdown` 〜 `onpointerup` /
          `onchange`）は自動非表示タイマーを一時停止し、操作中にコントロールが勝手に消えるのを防止。
- **高透過・グラスモーフィズム中央クイック操作ボタン群**:
    - コントロール表示時、画面中央にタッチフレンドリーな3連ボタン（`z-20`）を展開：
        - **10秒戻る**: 反時計回りの回転矢印（`RotateCcw`）の円ループ中央に `-10s` を埋め込み描画（シーク可能時）。
        - **大判 再生 / 一時停止**: 再生状態に応じて `Play` / `Pause` を切り替え。
        - **30秒進む**: 10秒戻しと対をなす逆回転（時計回り）の回転矢印（`RotateCw`）の円ループ中央に `+30s`
          を埋め込み描画（シーク可能時）。
    - **高い透過度と視認性の両立**:
        - 映像を遮らないよう高い透過度（シークボタン: `bg-black/20`、再生ボタン:
          `bg-blue-600/35`）を設定しつつ、`backdrop-blur-xs` と `drop-shadow-sm`
          により明暗いかなる映像背景でもクリアな視認性を確保。
    - **下部バーの重複ボタン廃止**:
        - 下部コントロールバーにあった「10秒戻る」「30秒進む」ボタンは廃止し、操作系を画面中央へ集約・整理。
- **実録画時間（duration）の多段階判定・途中録画時のシークバー長補正**:
    - **背景と課題**: 番組途中から録画を開始した際や放送延長・切り上げ時、番組表上の予定枠時間 `(endAt - startAt)`
      をそのままシークバー長に用いると、実際の映像尺とシークバーの長さが不一致になりシーク不能や再生停止位置のズレが生じる問題があった。
    - **解決策（3段階フォールバック）**:
        1. **動画ファイル実測 API (`/api/videos/:videoFileId/duration`)**: ffprobe /
           mp4box 等で計測された実ファイル尺を最優先（秒単位、ミリ秒変換）。
        2. **DB 記録の実測時間 (`recorded.duration`)**: 録画停止時に記録された実測ミリ秒（途中録画・中断・手動停止の実時間）。API
           (`/api/recorded`) の DTO にも `duration` を反映。
        3. **番組予定枠フォールバック**: 未取得時や live 配信時のフォールバックとして `(endAt - startAt)` を使用。
    - **途中録画時の開始時刻補正**:
        - 予定開始時刻から 30 秒以上遅れて録画が開始された場合、録画完了時に `recorded.startAt` も実開始時刻
          `actualStartAt` で自動補正し、録画一覧・詳細や時刻計算における整合性を担保。
    - **HLS 完了ストリームの追従**:
        - 録画済み HLS 視聴時、マニフェスト完了（`live === false`）時に `hls.media.duration`
          または全フラグメント総尺を検知しシークバーの最大長を実尺に自動同期。

## 5. リードオンリーモード（閲覧専用モード）仕様

### 5.1 導入の背景と目的

- 家族や同居人、ゲスト等と共有する環境において、「うっかり録画ファイルを削除してしまう」「予約やルールを変更してしまう」といったトラブルを防止する。
- デフォルトまたは設定により未認証アクセスを閲覧専用とし、ストリーミングやダウンロードなど許可された閲覧操作のみを提供しつつ、変更・破壊的操作は管理者パスワードによる一時アンロック制とする。

### 5.2 UI/UX 仕様

- **ヘッダーバッジ (`Header.svelte`)**:
    - リードオンリーモード有効時、ヘッダー右上にバッジを表示。
    - **閲覧専用状態**: 「🔒 閲覧専用」（クリックするとアンロックモーダル表示）。
    - **管理者モード状態**: 「🔓 管理者モード」（クリックすると再ロック・閲覧専用に戻すメニューやトグル）。
- **パスワード解除モーダル (`UnlockModal.svelte`)**:
    - 管理者パスワードを入力してアンロック。認証トークンはブラウザの `localStorage`
      に保持され、以降のリクエストに自動付与。
- **画面単位の閲覧・表示制御（`allowedOperations` による許可制）**:
    - **常時表示画面**:
        - **番組表 (`/guide`)**: 常に閲覧可能（予約追加・変更などのボタンのみ非表示）。
        - **録画一覧 (`/recorded`)**: 常に閲覧可能（削除・保護ボタンのみ非表示）。
        - **予約一覧 (`/reserves`,
          `/reserves/manual`)**: 常に閲覧可能（予約追加・削除・スキップ解除等の操作ボタンのみ非表示）。
    - **放送中 (`/onair`)**: `liveStream`
      権限と連動。許可時のみメニュー表示＆閲覧可能。非許可時はメニューから非表示化され、直接アクセス時は `/recorded`
      へ自動リダイレクト。
    - **許可制画面 (`dashboard`, `search`, `rules`, `encode`)**:
        - **ダッシュボード (`/`)**: `dashboard`
          許可時のみ表示。非許可時はメニューから非表示化され、トップページアクセス時は「録画一覧（`/recorded`）」へ自動リダイレクト。
        - **番組検索 (`/search`)**: `search` 許可時のみ表示。非許可時は非表示＆`/recorded` へリダイレクト。
        - **ルール一覧 (`/rule`)**: `rules` 許可時のみ表示。非許可時は非表示＆`/recorded` へリダイレクト。
        - **エンコード一覧 (`/encode`)**: `encode` 許可時のみ表示。非許可時は非表示＆`/recorded` へリダイレクト。
    - **管理者専用画面**:
        - **ルール編集 (`/rule/edit`)**: 管理者アンロック時のみアクセス可能。未認証時は `/rule`（または
          `/recorded`）へリダイレクト。
        - **システムログ (`/logs`)**: 管理者アンロック時のみアクセス可能。未認証時はメニュー非表示＆`/recorded`
          へリダイレクト。
- **再生選択モーダル (`StreamSelectModal.svelte`)**: MP4 の直接再生は常時選択可能とし、HLS/WebM トランスコード配信は
  `recordedStream` 許可時のみ選択可能に制御。

### 5.3 バックエンド保護との連携

- フロントエンドでのボタン非表示だけでなく、Hono の `readOnlyMiddleware` により API レベルで未認証リクエストを
  `403 Forbidden` (`error: 'readOnlyMode'`) で確実に遮断。
- **API ごとのアクセス遮断**:
    - `dashboard` 非許可: `GET /api/recording` を 403 遮断
    - `search` 非許可: `POST /api/schedules/search` を 403 遮断
    - `rules` 非許可: `GET /api/rules` を 403 遮断
    - `encode` 非許可: `GET /api/encode` を 403 遮断
    - `liveStream` 非許可: `/api/streams/live/...`, `/api/iptv/...` を 403 遮断
    - `recordedStream` 非許可: `/api/streams/recorded/...` を 403 遮断
    - 予約情報（`GET /api/reserves*`）: 常時閲覧可能（`POST`, `DELETE` 等の変更 API は 403 遮断）。
    - ストリーミング視聴セッションの維持（`PUT /api/streams/:id/keep`）および個別停止（`DELETE /api/streams/:id`）は、`liveStream`
      または `recordedStream` が許可されている場合は未認証時でも実行可能（一括停止 `DELETE /api/streams`
      は管理者専用として 403 保護）。
    - `download` 非許可: `GET /api/videos/...` のダウンロードクエリおよび M3U プレイリストを 403 遮断
    - 個別ルール詳細 API（`GET /api/rules/:id`）およびシステムログ API（`GET /api/logs`）は管理者専用のため閲覧専用時は常時 403 遮断。
- エンコード済み MP4 ファイル等の直接再生（`GET /api/videos/:id`）はサーバー負荷が低いため常時許可。
- 更新系リクエスト（POST, PUT, DELETE, PATCH 等）は未認証時は原則全面禁止（ストリーム維持・個別停止を除く）。

## 6. PWA・モバイル最適化・UI/UX 統一仕様

### 6.1 PWA (Progressive Web Apps) & 設定画面連動

- **Service Worker ライフサイクル管理 (`client/src/lib/utils/pwa.ts`)**:
    - 設定画面（`Settings.svelte`）の「PWA (ホーム画面追加)」トグルと連動。
    - トグル ON（デフォルト）時は `navigator.serviceWorker.register('/serviceWorker.js', { scope: '/' })`
      を実行。OFF 保存時は `navigator.serviceWorker.getRegistrations()` により全ワーカーを `unregister()`。
    - アプリ起動時（`main.ts`）に `localStorage` の設定値を自動読み込みして同期。
- **キャッシュ事故を防ぐ最小限 Service Worker (`client/public/serviceWorker.js`)**:
    - PWA インストール要件を満たす最小構成（Fetch イベントリスナー）のみを保持し、過剰なオフラインキャッシュによる「新バージョン JS が反映されない」「API レスポンスの滞留」「動画ストリーミングの妨害」等のトラブルを完全防止。
- **Web App Manifest & iOS メタタグ (`index.html`, `manifest.json`)**:
    - `display: standalone`、テーマカラー `#2563eb`、背景色 `#0f172a`。
    - `viewport-fit=cover`, `apple-mobile-web-app-capable="yes"`, `apple-mobile-web-app-status-bar-style="default"`,
      `apple-touch-icon` を完備。ホーム画面追加時に URL バーのないネイティブ全画面アプリとして起動。

### 6.2 動的ビューポート & セーフエリア最適化

- **動的ビューポート (`h-dvh`)**:
    - `App.svelte` の最外枠コンテナに `h-screen h-dvh`
      を適用し、モバイルブラウザのアドレスバー伸縮や PWA 全画面表示に追従。
- **Tailwind v4 セーフエリアユーティリティ (`app.css`)**:
    - `@utility pb-safe { padding-bottom: env(safe-area-inset-bottom, 0px); }`
    - `@utility pt-safe { padding-top: env(safe-area-inset-top, 0px); }`
    - `@utility mb-safe { margin-bottom: env(safe-area-inset-bottom, 0px); }`
    - メイン表示エリア（`main`）に `pb-safe` を付与し、iPhone の Home Indicator（下部バー）との重なりを防止。
    - モバイルドロワー（`Navigation.svelte`）に `pt-safe pb-safe` を付与。

### 6.3 レスポンシブ & 誤操作防止

- **予約一覧のスマホ最適化 (`Reserves.svelte`)**:
    - フィルタータブコンテナの親に `min-w-0 max-w-full`
      を適用し、子要素の横幅がスマホ画面を突き破って「重複」以降が切り取られる問題を解消。
    - スマホ時はタイトル＋手動予約ボタン（上段）と、カード枠内でスワイプできる横スクロールタブ（下段）の 2 段構成に最適化（PC時は 1 行構成を維持）。
    - スマホ時のタブ文字・パディングを `px-2.5 py-1.5 text-xs` に調整して一覧性を向上。
- **ルール一覧の誤操作防止ディバイダー (`Rule.svelte`)**:
    - カード表示（スマホ）およびテーブル表示（PC）の双方で、通常操作（「編集」ボタン）と破壊的操作（「削除/ゴミ箱」ボタン）の間にディバイダー（縦区切り線
      `w-px h-4 bg-slate-200 dark:bg-slate-700`）とマージン（`mx-1.5`）を配置。誤タップ・誤操作を物理的・視覚的に防止。
- **横スクロールタブの所作統一 (`no-scrollbar`)**:
    - `app.css` に `@utility no-scrollbar`（ベンダープレフィックス網羅）を定義。
    - 予約一覧・放送中（放送波タブ）・番組表（時間帯ジャンプ）に適用し、OS 既定の太いスクロールバーを排除して滑らかなスワイプ操作を提供。
- **全テーブル一覧の列幅・最小幅最適化と押しつぶされ防止 (`min-w-[...]` & `whitespace-nowrap`)**:
    - デスクトップ表示のテーブル（ルール一覧 `Rule.svelte`、録画一覧 `Recorded.svelte`、予約一覧
      `Reserves.svelte`、放送中 `OnAir.svelte`、ルール編集プレビュー
      `RuleEdit.svelte`）において、操作列の幅固定（`w-px whitespace-nowrap`
      または固定幅）に加え、各メタデータ列（日時、放送局、種別、時間/サイズ、ドロップ、状態等）に `whitespace-nowrap`
      と適切な `min-w-[...]` を設定。
    - 最重要コンテンツである「番組名 / 概要」「検索キーワード / 条件」には `min-w-[200px]`〜`min-w-[220px]`
      を保証し、中画面（768px〜1280px）でテーブル全体の横幅が狭まった際にも主役コンテンツが極端に押しつぶされる問題を根絶。コンテナ幅を下回った際は
      `overflow-x-auto` により破綻なく滑らかに水平スクロール可能。

### 6.4 タイポグラフィ・視認性統一

- **番組タイトル**: `.program-title` の PC サイズを 16px から **15px**
  に統一。録画一覧・予約一覧テーブルの文字サイズを統一。
- **番組概要・詳細テキスト**: モーダル・詳細画面向けに 12px から **14px**（`.program-description`,
  `.program-extended`）に引き上げ。
- **一覧概要スニペット**: カード・テーブルの概要スニペットを **スマホ 13px / PC 14px**（`.program-summary`）に拡大。
- **録画一覧テーブルの保護時位置ズレ修正**: 保護中番組（削除ボタン非表示時）に不可視プレースホルダー（`h-8 w-8`）を配置し、再生ボタン・保護ボタンの X 座標を完全に固定。

### 6.5 外部プレイヤー連携（URLスキーム / インテント起動）と M3U 導線廃止

- **課題と背景**:
    - 従来画面上に存在していた「M3U 保存」ボタンは、モバイルブラウザ上で単なるファイル保存にとどまり自動起動しない上、拡張子
      `.m3u8` によりプレイヤーが HLS マニフェストと誤認してパースエラーを引き起こす問題があった。
    - 一方で、サーバー設定 `config.yml` に定義されていた `urlscheme`（iOS: `vlc-x-callback://`, Android:
      `intent://...`）がクライアント UI から未参照のままとなっていた。
- **UI 改修・配置方針**:
    - クライアント UI から M3U プレイリスト保存導線を廃止。
    - 録画詳細（`RecordedDetail.svelte`）の各動画ファイル行に **「外部再生」** ボタン（`ExternalLink`
      アイコン）を新設。再生設定モーダル（`StreamSelectModal.svelte`）はブラウザ内再生設定（プロトコル・解像度選択）に専念させ、プロトコル選択と外部アプリ起動（元ファイル直接再生）の混同・誤認を防止するため外部再生導線を録画詳細の各ファイル行に一本化。
    - **ボタン配置順序**: 「再生」ボタンの直後に「外部再生」を並べ、その後に「ダウンロード」「削除」を配置して再生導線を一箇所に集約。
    - **デバイス別出し分け (`isMobileOrTabletDevice`)**:
      PC（デスクトップ）では不要な混乱を避けるため非表示とし、**スマホ・タブレット（iOS / iPadOS /
      Android）でのみ表示**。
- **起動仕様 (`client/src/lib/utils/urlScheme.ts`)**:
    - `detectClientOS`: ユーザーエージェントおよび `maxTouchPoints`（iPadOS 13+ デスクトップ UA 対応）から `ios`,
      `android`, `mac`, `win`, `other` を高精度に判別。
    - `openWithExternalPlayer`: UI 側の重複処理を一元化。サーバー設定 `urlscheme`（`video`,
      `m2ts`）テンプレートを展開し、`PROTOCOL`, `ADDRESS`, `FILENAME`
      を動的置換。リードオンリー解除トークン（`token`）も URL クエリへ自動伝搬。
    - `launchUrlScheme`: 非表示リンク（`<a>`）経由で安全に外部アプリ（VLC, MX Player 等）を呼び出し。
    - iOS のデフォルト URL スキーム設定を有料サブスク化された Infuse から完全無料の VLC（`vlc-x-callback://`）へ統一。
