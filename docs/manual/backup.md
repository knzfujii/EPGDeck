# データベースのバックアップとレストア

EPGDeck に保存されているデータベース情報（予約、録画済み番組、録画履歴、自動録画ルール）のバックアップおよびレストア（復元）手順について説明します。

バックアップデータはデータベース種別（SQLite / MySQL）に依存しない形式で出力されるため、MySQL で取得したバックアップを SQLite へ移行・レストアすることも可能です。

---

## バックアップ対象データ

- **含まれるデータ**:
  - 予約情報（`reserves`）
  - 録画済み番組情報（`recorded` / `videoFiles` / `thumbnails` / `dropLogFiles` / `recordedTags` の各メタデータ）
  - 録画履歴（`recordedHistory`）
  - 自動録画ルール（`rules`）

> [!NOTE]
> チャンネル情報（`channels`）は Mirakurun との接続時に自動的に取得・同期されるため、バックアップ対象外となっています。

- **含まれないデータ（別途手動でバックアップが必要）**:
  - 録画ファイル（`recorded/` 等の実動画ファイル）
  - サムネイル画像（`thumbnail/`）
  - ドロップログ（`drop/`）
  - ログファイル（`logs/`）
  - 設定ファイル（`config/config.yml`）

---

## バックアップ手順

以下のコマンドを実行してバックアップを作成します。

```bash
npm run backup [出力ファイル名]
```

### 実行例

```bash
npm run backup backup_20260831.json
```

実行後、指定したファイル名（JSON 形式）でバックアップデータが出力されます。

---

## レストア（復元）手順

新しい環境または初期化後の環境でバックアップデータを復元します。

1. `config/config.yml` に接続先データベース（SQLite または MySQL）を設定します。
2. 以下のコマンドを実行してデータを復元します。

```bash
npm run restore [バックアップファイル名]
```

### 実行例

```bash
npm run restore backup_20260831.json
```

> [!WARNING]
> レストアを実行すると、既存のデータベーステーブルのデータが上書き・復元されます。既存データが存在する場合は事前にバックアップを取得してください。

---

## EPGStation から移行時のサムネイル階層化（マイグレーション）

EPGStation からサムネイル画像（`thumbnail/` フォルダ）をコピー・移行した場合、すべての画像ファイルが同一ディレクトリ直下にフラットに配置されています。

EPGDeck ではファイルの集中によるパフォーマンス低下を防ぐため、`recordedId % 100` による2桁サブディレクトリ（`00/`〜`99/`）への分散配置（シャーディング）を採用しています。

移行したフラットなサムネイルファイルを一括でサブディレクトリへ移動し、データベース情報を更新するには以下のマイグレーションコマンドを実行します：

```bash
# 事前確認（ファイルの移動やDB更新を行わずにシミュレーション）
npm run migrate-thumbnails -- --dry-run

# 実際にマイグレーションを実行
npm run migrate-thumbnails
```
