## 1. 録画予約の種類

EPGDeck には、予約の作成方法によっていくつかの種類があります。

| 種類 | 作成方法 | 特徴 |
|---|---|---|
| **個別予約** | 番組表（ガイド）・番組検索・放送中一覧から番組をクリックして予約 | その番組だけを録画。設定は予約ごとに個別に変更可能 |
| **ルール予約** | ルール一覧でキーワード・放送局・ジャンル等の条件を設定 | 条件に一致する番組を自動で予約。設定はルール側で管理 |
| **時間指定予約** | 予約一覧の「手動予約を追加」から日時と放送局を指定 | 番組表にない時間帯も録画可能 |

## 2. 録画オプションの設定

番組をクリックして表示される詳細画面（または予約一覧の詳細画面）では、以下の録画オプションを設定できます。

### TS保存先

録画した TS ファイルの保存先を指定します。

- **親ディレクトリ**: 保存先ディレクトリ名をドロップダウンから選択します。「デフォルト」を選ぶとシステムが自動で保存先を決定します。
- **サブディレクトリ**: 親ディレクトリ配下のサブディレクトリを指定できます（任意）。未入力の場合は親ディレクトリ直下に保存されます。

> **注意**: サブディレクトリを指定する場合は、親ディレクトリも明示的に指定することを推奨します。親ディレクトリが「デフォルト」のままサブディレクトリだけ指定すると、意図した場所に保存されない可能性があります。

### エンコード設定

録画完了後に自動でエンコード（変換）する設定です。最大 **3 つまで** 同時に指定できます。

- **エンコードモード**: エンコードプリセット名を選択します。「エンコードなし」を選ぶとその行は無効になります。
- **保存先**: エンコード後のファイルの保存先を、親ディレクトリとサブディレクトリで指定できます（任意）。

「追加」ボタンでエンコード行を増やし、各行の削除ボタン（ゴミ箱アイコン）で削除できます。

### TSファイル削除

「エンコード完了後に元のTSファイルを削除する」にチェックを入れると、エンコードが完了した後に元の TS ファイルを自動で削除します。

- エンコード設定が 1 つ以上ある場合に有効です。
- エンコード設定がない場合は、この設定は無効です（TS ファイルは削除されません）。

## 3. 末尾欠け許可（allowEndLack）について

チューナー数が不足して予約が時間重複した際、先に録画中の番組の末尾を切り上げて後続の予約を開始するかどうかを制御します（デフォルト: `false` 不許可）。

| 設定 | 動作 |
|---|---|
| **許可 (`true`)** | 先の録画の末尾数分を切り上げ、後続の予約を確実に録画開始する |
| **不許可 (`false`)** | 先の録画を最後まで録画しきる。重なった後続予約は録画しない（競合扱い） |

## 4. 予約一覧からの編集

予約一覧（`/reserves`）で予約をクリックすると、詳細画面が表示されます。

### 個別予約の場合

個別予約（番組表・検索・放送中一覧から作成した予約）では、詳細画面で以下の設定を直接編集できます。

- TS保存先（親・サブディレクトリ）
- エンコード設定（最大3つ）
- TSファイル削除
- 末尾欠け許可

「設定を更新」ボタンを押すと、変更が予約に反映されます。

### ルール予約の場合

ルール予約（自動録画ルールで作成された予約）では、詳細画面に「ルールを編集する」ボタンが表示されます。

ルール予約の録画オプションは**ルール側で管理**されているため、予約一覧から直接編集することはできません。「ルールを編集する」ボタンを押すと、ルール編集ページに移動してルールの設定を変更できます。

## 5. 録画中番組の操作（途中完了・中断・取り消し）

録画が進行している最中の番組に対し、予約一覧・番組表・放送中画面などから停止操作を行った場合、以下の **3 択アクションモーダル** が表示されます。用途に合わせて安全に挙動を選択できます。

| 選択肢 | 動作 | 主な用途 |
|---|---|---|
| **完了として保存** | 録画ストリームを正常終了し、実時間を確定させてサムネイル・エンコード・**録画履歴（`recorded_history`）への登録** を通常通り実行 | 目的のシーンまで録画できたため、正常に録画完了として保存し二重録画防止の対象にしたい場合 |
| **中断して保存（未完了）** | 書き込み途中の動画ファイルを保存・エンコードするが、未完了扱いとして **録画履歴には登録しない** | トラブルや時間切れで途中までしか録画できなかったがファイルは残したい場合（再放送時に重複スキップされず録画可能） |
| **録画を取り消し（破棄）** | 録画ストリームを即座に停止し、書き込み途中の TS ファイルや DB レコードを **物理削除して完全クリーンアップ** | 誤って録画開始した番組をキャンセルし、ゴミファイルを残したくない場合 |

## 6. ルール予約と個別予約の関係

### ルール予約は「ルールのコピー」として作られる

ルール予約は、ルールの設定（保存先・エンコード設定・末尾欠け許可など）を**コピーして**作成されます。

ルールが更新されるたびに、ルールに一致する予約が再生成され、ルールの最新設定が再コピーされます。

### 個別編集はルール更新で上書きされる

ルール予約を個別に編集しても、**次にルールが更新されるとルール側の設定に戻ってしまいます**。

そのため、ルール予約の録画オプションを変更したい場合は、**ルール自体を編集**してください。

### まとめ

| 予約タイプ | 録画オプションの編集方法 |
|---|---|
| **個別予約** | 予約一覧の詳細画面から直接編集 |
| **ルール予約** | ルール編集ページでルール自体を編集 |

## 7. 重複録画の回避（二重録画防止）

ルールで「重複録画を回避する」を有効にすると、過去に録画した番組（再放送等）を自動検知して「重複スキップ」にします。

### 判定条件（すべて合致で重複）
1. **同一放送局 (`channelId`)**: 局が異なる（地デジ ⇄ BS等）場合は別物として録画。
2. **コアタイトルの一致**: `[字]`, `[新]`, `[再]` 等の記号および角括弧 `[...]` を除去したタイトルで比較。
3. **期間内（設定時）**: `重複を避ける期間（日数）` を指定した場合、その期間内の録画履歴のみ照合（空欄または 0 は無期限）。

> [!NOTE]
> 正常完了した番組指定予約（ルールおよび手動個別予約）のみが履歴に記録されます。中断（`stop`）や異常終了した番組は再放送救済のため履歴に残りません。

### 手動解除
再放送を録画したい場合は、予約一覧の詳細ダイアログから「重複手動解除」を実行すると、その回のみ通常の予約に戻ります（次回以降のルール更新でも維持）。

## 8. チューナー競合（時間重複）の仕組み

同時予約数が物理チューナー数を超過した状態（`isConflict`）の調停仕様です。

### 優先順位
1. **手動個別予約**（最優先）
2. **手動時間指定予約**
3. **ルール予約**（ルール ID 昇順）

※重複スキップ中の番組はチューナーを消費しません。

### 競合解消方法
- 重複する別番組を手動「スキップ」にする
- 先行番組の「末尾欠け許可」を有効にする
- チューナーを増設する

## 9. 放送波追従（番組延長・イベントリレー・短時間番組保護）

内蔵の ARIB 解析エンジン（`packages/arib-probe`）が放送波の番組情報（EIT）を常時監視し、放送時間の変動に自律追従します。

- **番組延長への追従**: 放送波（EIT[p/f]）から新終了時刻を取得して終了タイマーを動的延長。前番組延長に伴う後続番組の開始繰り下げ（Delay）時もタイマーを自動再スケジュール。
- **チューナー競合の即時再調停**: 延長・繰り下げで後続予約と衝突した際は、該当時間帯のチューナー重複判定（`recheckConflicts`）を即座に再実行して優先度順に再割り振り。
- **イベントリレー追従**: ナイター中継の続きがサブチャンネルや別局で放送される際、イベントリレー記述子を検知して録画先ストリームを自動切替。
- **短時間番組保護**: 5分以下のミニ番組は、EIT 未送出によるタイムアウトを防ぐためサービス指定ストリームへ自動切替して即時録画。

## 10. ドロップチェックとログ管理（Drop Log）

録画中の TS パケット損失（Error / Drop / Scrambling）をリアルタイム監視し、集計値を DB に記録します。

### ドロップ0件時のログ自動削除 (`deleteOnNoDrop: true`)
- エラー・ドロップが0件の録画は、ディスク圧迫を防ぐためログ実ファイルを自動削除します（デフォルト有効）。
- ログファイルが削除されても **DB 上の集計値（Drop: 0）は永続保持** されます。ドロップ発生時のみログ実ファイル（`%ROOT%/drop/<ファイル名>.log`）が残ります。

### ドロップログクリーンアップ
サーバー起動時および手動 API 実行時に、孤立ログファイルや不要な0件ログをディスクから自動整理します。

## 11. 自動削除・クリーンアップ仕様（注意事項）

通常運用で録画ファイルが勝手に消えることはありませんが、以下の機能・設定に留意してください。

| 機能 / 設定 | 削除条件 | 注意事項 |
| :--- | :--- | :--- |
| **録画クリーンアップ** (`POST /api/recorded/cleanup`) | DB 未登録の孤立ファイル、および実ファイル不在の DB レコード | Web UI には非搭載（安全設計）。API 実行時は NAS アンマウント時の誤削除等に注意 |
| **元 TS 自動削除** (`isDeleteOriginalAfterEncode`) | エンコード正常完了時 | TS を残したい場合は予約・ルールのチェックを外す |
| **ストレージ容量制限** (`limitThreshold`) | 空き容量が閾値を下回った場合 | 古い録画から自動削除（デフォルトは未設定・無効） |
| **録画失敗ファイル削除** | 録画開始時のストリーム受信タイムアウト (5秒) | 破損・0バイトファイルを自動削除 |
| **二重録画防止履歴保持** (`historyRetentionDays`) | 指定日数（デフォルト 90日）経過後 | `0` 指定で無期限保持 |
