# ARIB TR-B14 / TR-B15 実装仕様リファレンスガイド

本書は、日本のデジタル放送規格である **ARIB TR-B14**（地上デジタルテレビジョン放送運用規定）および **ARIB TR-B15**（BS/広帯域CSデジタル放送運用規定）に準拠したアプリケーション（TSパケットパーサー、EPG取得エンジン、選局・録画マネージャー、プレイヤー等）を設計・実装するための技術リファレンスです。

> **出典および免責事項**:
> 本資料は、一般社団法人電波産業会（ARIB）が公開する標準規格（ARIB STD-B10, STD-B24, STD-B32 等）および技術資料（ARIB TR-B14, TR-B15 等）に基づき、本ソフトウェア（`arib-probe`）の設計・開発上の要点を独自に整理・要約した解説資料です。規格の正式な仕様原文は ARIB 公式文書をご参照ください。

## 1. 規格の位置づけとアーキテクチャ概要

ARIB（電波産業会）の規格体系において、**STD（標準規格）**がビット配列やパケット構造などのプロトコル定義を行うのに対し、**TR（技術資料）**は放送波上での具体的なパラメータ、再送周期、記述子の制約、受信機の振る舞いなどの「相互運用ガイドライン」を定義しています。

```
+-------------------------------------------------------------------+
|                        アプリケーション層                         |
|   (UI / EPG表示 / 選局エンジン / 録画スケジューラ / 再生プレイヤー)   |
+-------------------------------------------------------------------+
|               運用規定 (ARIB TR-B14 / ARIB TR-B15)                |
|  ・ID体系と選局規則    ・PSI/SI再送周期と運用制約    ・イベントリレー   |
|  ・NHK/民放の運用差異  ・局別エッジケース対応        ・文字コード運用   |
+-------------------------------------------------------------------+
|                        基盤標準規格 (ARIB STD)                    |
|  ・STD-B10 (PSI/SI)    ・STD-B25 (CAS/スクランブル)  ・STD-B31 (ISDB-T)   |
|  ・STD-B32 (多重化/MPEG)・STD-B24 (字幕/データ放送)   ・STD-B21/B20 (受信機)|
+-------------------------------------------------------------------+
|                        MPEG-2 Transport Stream                    |
+-------------------------------------------------------------------+
```

### 主要参照規格
- **ARIB STD-B10**: 番組配列情報（SI）の構文と基本定義
- **ARIB STD-B32**: 映像・音声符号化（MPEG-2 Video, H.264/AVC, AAC）および多重化
- **ARIB STD-B24**: データ放送および文字コード体系（8bit ARIB外字・追加漢字）
- **ARIB TR-B14**: 地上デジタルテレビジョン放送運用規定（Vol.1 - Vol.8）
- **ARIB TR-B15**: BS/広帯域CSデジタル放送運用規定

## 2. 放送波識別子体系（DVB 3要素 + 追加識別子）

日本のデジタル放送において、番組（イベント）やサービス（チャンネル）を一意に特定するための識別子体系です。

| 識別子 (フィールド名) | ビット幅 | 役割と採番ルール |
|---|---|---|
| **original_network_id** (`ONID`) | 16-bit | 原送出ネットワークの識別子。<br>・地デジ: 各局・親局ごとに割り当て（`0x7FE0`〜`0x7FEF` 等）<br>・BSデジタル: `0x0004`<br>・110度CS: `0x0006` (CS1), `0x0007` (CS2) |
| **transport_stream_id** (`TSID`) | 16-bit | 物理変調波（TS）の識別子。<br>・地デジ: 原則 `(original_network_id << 10) | (TSスロット)` 等で運用<br>・BS: トランスポンダ番号やスロットに対応 |
| **service_id** (`SID`) | 16-bit | TS内の個別サービス（編成チャンネル）。PATの `program_number` と同値。 |
| **event_id** | 16-bit | 1つのサービス内における個別番組の識別番号。同一サービス内で一意（過去・未来で再利用あり）。 |

> **選局の一意キー**: 通常は `(original_network_id, transport_stream_id, service_id)` の3つ（DVB Triplet）でサービスを一意に識別します。

### 地上波の論理チャンネル（3桁番号）マッピング
地上波の選局では、リモコンキーID（1〜12）と、サービスごとの3桁チャンネル番号（例: `011`, `012`, `021`）の変換が必要です。
- **3桁番号体系**: `[リモコンキーID (1桁)] + [サービス番号 (2桁)]`
  - 例: リモコン1chのメインサービスは `011`、サブチャンネルは `012`, `013`
- 3桁番号は、NITの `service_list_descriptor` および SDTの `service_descriptor`、または `ts_information_descriptor`（地上波独自）内のリモコンキーID紐付け情報から算出します。
- **部分受信（ワンセグ）**: サービス種別 `0xC0`（データ放送）または専用TVサービスIDが割り当てられ、PAT/PMTで13セグメント中の階層A（中央1セグ）として多重化されます。

## 3. 多重化構成と必須 PSI/SI テーブル

MPEG-2 TS（パケット長 188バイト）において、アプリケーションが購読すべき標準PIDおよびテーブルID一覧です。

```
MPEG-2 TS (188 bytes packet)
├── PID 0x0000: PAT (Program Association Table) -> 各PMTのPIDを案内
├── PID 0x0010: NIT (Network Information Table) -> 物理周波数、ネットワーク名
├── PID 0x0011: SDT (Service Description Table) -> サービス名、事業者名
├── PID 0x0012: EIT (Event Information Table)   -> 番組名、放送時間、詳細情報
├── PID 0x0014: TDT/TOT (Time Offset Table)     -> JST時刻情報、閏秒情報
└── PID 0x0020~: PMT (Program Map Table)        -> 映像・音声・字幕PIDの案内
```

### 3.1 主要テーブルとPID対応表

| テーブル略称 | テーブル名称 | PID (hex) | Table ID (hex) | TR-B14 (地デジ) | TR-B15 (BS/CS) |
|---|---|---|---|---|---|
| **PAT** | Program Association Table | `0x0000` | `0x00` | 必須（最長100ms周期） | 必須（最長100ms周期） |
| **CAT** | Conditional Access Table | `0x0001` | `0x01` | 有料放送/スクランブル時 | 必須 |
| **PMT** | Program Map Table | PATで指定 | `0x02` | 必須（最長100ms周期） | 必須（最長100ms周期） |
| **NIT** | Network Information Table | `0x0010` | `0x40` (自), `0x41` (他) | 必須（自のみ運用） | 必須（自・他） |
| **SDT** | Service Description Table | `0x0011` | `0x42` (自), `0x46` (他) | 必須（自のみ運用） | 必須（自・他） |
| **BAT** | Bouquet Association Table | `0x0011` | `0x4A` | 任意（通常非運用） | CS等で事業者グループに使用 |
| **EIT [p/f]** | Event Information Table (Present/Following) | `0x0012` | `0x4E` (自), `0x4F` (他) | 必須（最長2秒周期、通常0.5〜1秒） | 必須 |
| **EIT [sch]** | Event Information Table (Schedule) | `0x0012` (`0x0026`/`0x0027`等) | `0x50`-`0x5F` (自Basic)<br>`0x60`-`0x6F` (自Ext) | 同一PID(`0x0012`)で送出 | H-EIT/M-EIT/L-EIT別PID運用 |
| **TDT / TOT**| Time Offset Table | `0x0014` | `0x70` (TDT), `0x73` (TOT) | 日本時間(JST)同期にTOT必須 | 日本時間(JST)同期にTOT必須 |
| **BIT** | Broadcaster Information Table | `0x0024` | `0xC4` | 必須（SI送信情報・局情報） | 必須 |
| **CDT** | Common Data Table | `0x0029` | `0xC8` | ロゴデータ等の取得 | ロゴデータ等の取得 |

## 4. 地上デジタル（TR-B14）特有の仕様

### 4.1 イベントリレーとマルチ編成（Event Group Descriptor）
スポーツ中継の延長等に伴う「マルチ編成移行」や「他チャンネルへの引き継ぎ」の運用規定です。

- **記述子**: `event_group_descriptor` (`tag: 0xD6`)
- **`group_type` の定義 (ARIB STD-B10 第2部 5.2.16 準拠)**:
  - **`0x01`（イベント共有 / Event Sharing）**: 同一TS内のマルチ編成（メインとサブチャンネルで同一番組を並行・分岐放送）。
  - **`0x02`（イベントリレー / Event Relay）**: 放送延長時に別チャンネル（例: NHK総合 ➔ Eテレ、独立局の別サービス等）へ番組を引き継ぎ。
  - **`0x04`（イベント移動 / Event Movement）**: 別の日時や別チャンネルへ枠移動。

## 5. BS / 広帯域CS（TR-B15）特有の仕様

### 5.1 EITの階層運用（H-EIT, M-EIT, L-EIT）
BSおよびCSでは帯域制約と選局・EPG描画速度のバランスをとるため、EITが詳細度に応じて分かれて配信されます。

| 階層種別 | PID | 送信内容 | 目的・用途 |
|---|---|---|---|
| **H-EIT** (High) | `0x0012` | 全イベントの詳細情報（番組解説・拡張記述子含む） | 自TSの詳細EPG（直近8日分） |
| **M-EIT** (Middle) | `0x0026` | 簡易情報（番組名、開始終了時刻、ジャンル） | 他TSを含む広域EPG高速一覧用 |
| **L-EIT** (Low) | `0x0027` | 最小限の番組メタデータ | 最小フットプリント受信機用 |

## 7. NHKと民放・プラットフォーム別の運用差異とエッジケース

### 7.1 NHKと民放の運用ポリシー比較

| 項目 | NHK（総合・Eテレ） | 民放（キー局・ローカル局） |
|---|---|---|
| **音声多重の形式** | **デュアルモノラル（1/0 + 1/0）**を多用 | **デュアルステレオ（2/0 × 2系統）**が主流 |
| **イベントリレー** | 極めて動的かつ高頻度（総合 ⇔ Eテレ間） | 稀（野球延長時の同一TS内サブch移行等） |
| **EIT変更の即時性** | 国会・特報・災害時に即時書き換え | 枠の定時運行が基本、変更頻度は低め |
| **文字コード（外字）** | 第3/第4水準、ARIB拡張外字を多用 | 常用漢字中心、ひらがな代替表記が多い |
| **深夜休止中の挙動** | EIT[p/f]に「放送休止」イベントを常時送出 | EIT更新停止、または最小限パケットのみ |

#### 音声形式：デュアルモノラルのハンドリング
- **民放**: 副音声付き番組（2か国語放送等）は、PMTに第1音声PID（ステレオ）と第2音声PID（ステレオ）の2本を立てることが多い。
- **NHK**: 伝統的に**1本のAAC音声ストリーム内に左チャンネル（主音声）、右チャンネル（副音声）を混合する「1/0 + 1/0 モード」**（`component_type == 0x02`）を採用。プレイヤー側で「左のみ両耳」「右のみ両耳」へダウンミックスする処理が必要。

### 7.2 プラットフォーム別エッジケース
- **110度CS放送（スカパー！）の共通EPG TS**:
  - 各TSに個別EIT-Scheduleを送出せず、特定のトランスポンダ（ND16等の通称「共通EPG TS」）に全サービスのEIT-Scheduleを集約送出。自TSのEIT-Scheduleを永久待機しないタイムアウト設計が必要。
- **地方独立UHF局の動的マルチ編成（HD+SD分割）**:
  - 野球中継等でメインチャンネル（HD 1080i）からメイン（HD/SD）＋サブ（SD 480i）への分割が動的に発生。PMTの `version_number` 更新を監視してデコーダを再初期化する必要がある。
- **CATV（ケーブルテレビ）の再送信環境**:
  - 周波数変換パススルーやトランスモジュレーションでは、NITのNetwork IDやTSIDがCATV独自（`0xFFXX` 等）に置換される場合がある。地デジ規格値（`0x7FE0`〜`0x7FEF`）のみに限定するバリデーションはスキャン失敗を招く。

## 8. 堅牢なアプリケーション実装のためのエンジニアリングノウハウ

### 1. EIT[p/f] と EIT-Schedule の競合調停（最優先原則）
- EIT-Schedule（先1週間分）は低頻度で循環しているため、突発的な時間延長や休止が発生した際、スケジュール側の更新が数分〜数十分遅れます。
- **原則**: **「直近2番組（現在・次）の情報は、EIT-Scheduleの内容よりも EIT[p/f]（PID 0x0012, TID 0x4E）を最優先で正とする」**。録画中の延長追従や開始待機は EIT[p/f] の受信をトリガーに行います。

### 2. `event_id` を主キーとして過信しない
- 番組短縮・突発的な休止の際、局によっては既存の `event_id` の長さを縮めるのではなく、既存イベントを削除して新規 `event_id` で埋め直す運用を行う場合があります。
- **対策**: 予約エンジンでは `service_id` + `event_id` の完全一致だけでなく、**放送予定時刻の近傍チェック（開始時刻 ± 数分）**を照合キーとして併用します。

### 3. PMTの `version_number` 監視とパーサーの再初期化
- 放送解像度の切り替え（1080i ⇔ 720p/480i）や音声ストリーム構成の変更（ステレオ ⇔ 5.1ch）は、PMTパケットヘッダの `version_number`（5-bit）のインクリメントで示されます。この変化を検知して内部バッファやデコーダをリセットすることで再生破綻を防ぎます。

### 4. 日時データ（MJD / BCD）と TOT 時刻同期
- TOT（Time Offset Table: PID `0x0014`）から得られる日本標準時（JST）は、**修正ユリウス日（MJD 16-bit）** と **BCD形式（24-bit: HH:MM:SS）** で表現されます。
- システムのOSクロックのズレに影響されず、ストリーム内のTOTパケットでJST基準時刻を定期補正します。

$$JST = \text{MJD\_to\_Date}(mjd) + \text{BCD\_to\_Time}(bcd)$$

```c
// MJDから年月日(Y, M, D)への標準変換計算 (ARIB STD-B10 付録C)
int y_prime = (int)((mjd - 15078.2) / 365.25);
int m_prime = (int)((mjd - 14956.1 - (int)(y_prime * 365.25)) / 30.6001);
int d = mjd - 14956 - (int)(y_prime * 365.25) - (int)(m_prime * 30.6001);
int k = (m_prime == 14 || m_prime == 15) ? 1 : 0;
int year = 1900 + y_prime + k;
int month = m_prime - 1 - k * 12;
```

### 5. ARIB STD-B24 文字コードデコード
- 番組名・概要テキストは、ARIB STD-B24 の8単位符号（JIS X 0208 + エスケープシーケンス + ARIB 外字マップ）でエンコードされています。
- `[字]`, `[解]`, `[二]`, `[新]`, `[再]` 等の囲み記号や追加文字を Unicode（通常文字または外字領域）へマッピングして UTF-8 化します。
